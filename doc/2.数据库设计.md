你现在已经确定了技术栈：**Node.js + Socket.IO + MongoDB**，
接下来这一步——**数据库设计（Data Schema 设计）**非常关键，它决定了系统扩展性和性能。

下面是一个为 **用户间在线聊天系统** 精心设计的 MongoDB 数据模型方案，
兼顾 **实时性能**、**查询效率**、**消息持久化**、**后期扩展（群聊、客服、推送等）**。

# 🧱 一、数据库概览

| 集合 (Collection)        | 用途          | 是否核心  |
| ---------------------- | ----------- | ----- |
| `users`                | 用户账户与资料     | ✅ 核心  |
| `conversations`        | 会话（单聊/群聊）   | ✅ 核心  |
| `messages`             | 聊天消息        | ✅ 核心  |
| `user_status`          | 在线状态、最后活跃时间 | ✅ 核心  |
| `attachments`          | 文件/图片消息存储引用 | ⚙️ 可选 |
| `system_notifications` | 系统广播与公告     | ⚙️ 可选 |
| `blocked_users`        | 黑名单         | ⚙️ 可选 |

# 🧩 二、核心数据模型设计

## 1️⃣ users（用户表）

**功能**：存储用户基本信息、认证信息、权限角色。

```js
{
  _id: ObjectId,
  username: String,               // 用户名（唯一）
  email: String,
  passwordHash: String,           // bcrypt 哈希
  avatar: String,                 // 头像URL
  role: "user" | "admin",         // 用户角色
  createdAt: Date,
  updatedAt: Date,
  lastSeen: Date,                 // 最后活跃时间
  online: Boolean,                // 是否在线（可缓存）
  bio: String,                    // 简介（可选）
  settings: {                     // 用户配置（可选）
    darkMode: Boolean,
    notification: Boolean
  }
}
```

🔹 **索引建议：**

```js
db.users.createIndex({ username: 1 }, { unique: true })
db.users.createIndex({ email: 1 }, { unique: true })
db.users.createIndex({ online: 1 })
```

---

## 2️⃣ conversations（会话表）

**功能**：定义用户之间（或群组）的聊天会话。

```js
{
  _id: ObjectId,
  type: "private" | "group",      // 会话类型：单聊 / 群聊
  participants: [ObjectId],       // 成员列表（用户ID数组）
  lastMessage: ObjectId,          // 最近一条消息ID
  lastMessageAt: Date,            // 最近消息时间
  unreadCount: {                  // 每个用户的未读计数
    "userId1": Number,
    "userId2": Number
  },
  name: String,                   // 群聊名（仅 type=group）
  avatar: String,                 // 群头像（仅 type=group）
  createdBy: ObjectId,            // 创建者
  createdAt: Date,
  updatedAt: Date
}
```

🔹 **索引建议：**

```js
db.conversations.createIndex({ participants: 1 })
db.conversations.createIndex({ updatedAt: -1 })
```

💡 **设计要点：**

* 每个用户和另一用户（或群组）共享一个 `conversation`。
* 聊天列表页查询时按 `updatedAt` 倒序分页。
* `unreadCount` 可在写消息时更新。

---

## 3️⃣ messages（消息表）

**功能**：存储所有聊天消息内容（文本、图片、文件等）。

```js
{
  _id: ObjectId,
  conversationId: ObjectId,       // 所属会话
  senderId: ObjectId,             // 发送者
  receiverId: ObjectId,           // 接收者（私聊）或 null（群聊）
  type: "text" | "image" | "file" | "system",
  content: String,                // 消息正文或文件URL
  metadata: {                     // 附加信息
    fileName: String,
    fileSize: Number,
    mimeType: String
  },
  status: "sent" | "delivered" | "read",
  createdAt: Date,
  updatedAt: Date,
  deleted: Boolean,               // 是否撤回/删除
  readBy: [ObjectId]              // 已读用户（群聊时使用）
}
```

🔹 **索引建议：**

```js
db.messages.createIndex({ conversationId: 1, createdAt: 1 })
db.messages.createIndex({ senderId: 1, createdAt: -1 })
db.messages.createIndex({ receiverId: 1, createdAt: -1 })
```

💡 **设计要点：**

* **分页历史消息**：根据 `conversationId + createdAt` 做索引。
* **撤回消息**：`deleted: true`，前端可显示“消息已撤回”。
* **未读消息**：可通过 `status` 或 `readBy` 字段计算。

---

## 4️⃣ user_status（在线状态表）

**功能**：维护用户在线、Socket 连接信息、最后活动时间。

> 在分布式部署时，推荐同步 Redis，以便实时广播。

```js
{
  _id: ObjectId,              // 用户ID
  socketId: String,           // 当前连接ID
  online: Boolean,
  lastSeen: Date,
  ip: String,
  userAgent: String
}
```

🔹 **索引建议：**

```js
db.user_status.createIndex({ online: 1 })
```

💡 **设计要点：**

* 用户上线时 `insert / update online=true`；
* 断线时 `online=false, lastSeen=now()`；
* 管理员端可实时看到谁在线。

---

## 5️⃣ attachments（附件表，可选）

**功能**：文件 / 图片 / 视频消息引用，支持多种存储方式（本地、S3、OSS）。

```js
{
  _id: ObjectId,
  messageId: ObjectId,
  uploaderId: ObjectId,
  type: "image" | "file" | "video",
  url: String,                 // 文件访问URL
  size: Number,                // 文件大小
  mimeType: String,
  storage: "local" | "s3" | "oss",
  createdAt: Date
}
```

---

## 6️⃣ system_notifications（系统通知，可选）

**功能**：管理员发布的全局通知 / 公告。

```js
{
  _id: ObjectId,
  title: String,
  content: String,
  createdBy: ObjectId,
  createdAt: Date,
  target: "all" | [ObjectId],  // 目标用户或群组
  type: "announcement" | "update" | "alert"
}
```

---

## 7️⃣ blocked_users（黑名单，可选）

**功能**：屏蔽或拉黑其他用户。

```js
{
  _id: ObjectId,
  userId: ObjectId,
  blockedId: ObjectId,
  createdAt: Date
}
```

# ⚙️ 四、典型查询场景

| 场景         | 查询方式                                                                   |
| ---------- | ---------------------------------------------------------------------- |
| 获取用户最近聊天列表 | `conversations.find({ participants: userId }).sort({ updatedAt: -1 })` |
| 获取某会话历史消息  | `messages.find({ conversationId }).sort({ createdAt: -1 }).limit(50)`  |
| 统计未读消息数    | `conversations.unreadCount[userId]`                                    |
| 搜索聊天记录     | `messages.find({ content: /keyword/i, senderId: userId })`             |
| 获取在线用户     | `user_status.find({ online: true })`                                   |

# 📊 五、性能优化建议

| 项目        | 建议                                   |
| --------- | ------------------------------------ |
| **消息量大**  | 使用 capped collection 或消息分表（按月份/会话分片） |
| **高并发在线** | Redis 存 socket 状态、事件广播               |
| **未读计数**  | MongoDB 原子更新：`$inc`、`$set`           |
| **索引管理**  | 重点索引 `conversationId + createdAt`    |
| **数据归档**  | 定期归档历史消息到冷存储（S3/OSS）                 |
